JavaScript 的两种定时器

setTimeout 只执行一次，setInterval 按间隔反复执行； 两者都由浏览器计时，配合 clearTimeout / clearInterval 可以随时取消。

一、语法与特点对照

setTimeout / setInterval

setTimeout()

一次性延时定时器 · 只执行一次

// 延时 2 秒后执行一次回调 const id = setTimeout(function () { console.log("时间到！"); }, 2000); // 取消尚未执行的延时 clearTimeout(id);

执行次数1 次
返回值数字 id（用于清除）
清除方法clearTimeout(id)
典型场景延迟提示、防抖、轮播自动切换、动画收尾

setInterval()

循环定时器 · 每隔一段时间执行一次

// 每隔 1 秒执行一次回调 const id = setInterval(function () { console.log("滴答"); }, 1000); // 必须手动停止，否则会一直执行 clearInterval(id);

执行次数无限次（直到被清除）
返回值数字 id（用于清除）
清除方法clearInterval(id)
典型场景时钟、秒表、进度轮询、轮播自动播放

四、实验三：定时器与事件循环的执行顺序

即使延时为 0 也不会立即执行

定时器的回调属于宏任务，必须等当前同步代码全部执行完才会进入队列； Promise 的回调属于微任务，会先于宏任务执行。

五、两种定时器对照表

速查
对比项 setTimeout setInterval
执行次数 只执行 1 次 每隔 delay 毫秒执行 1 次，直到清除
是否自动停止 执行完自动失效 不会自动停止，必须 clearInterval

递归替代 在回调里再次调用自身可模拟循环 用递归 setTimeout 可避免任务堆积

六、使用要点

  • 最小延时限制：浏览器对嵌套定时器有最小间隔（通常 4ms 起），setTimeout(fn, 0) 依旧会被推迟到下一个宏任务，不会同步执行。
  • 不精确：定时器只保证“至少等待”这么久，实际时间受主线程忙闲影响，秒表类需求应用 Date.now() 计算真实差值。
  • 记得清除：组件卸载、页面跳转或重复点击时先 clearTimeout / clearInterval，否则会重复执行或内存泄漏。
  • 递归 setTimeout：需要可变间隔或避免堆积时，用 setTimeout 在回调内再调用自己，比 setInterval 更可控。
  • 参数传递：setTimeout(fn, 1000, "hello") 中第三个及以后的参数会作为回调实参传入。
  • 页面隐藏：切换标签页或最小化时，浏览器会降频甚至暂停计时，恢复后可能出现“补执行”现象。
