Promise + async/await 包饺子

每个步骤都是一个 Promise（内部用 setTimeout 模拟耗时）： 买原料（线上 ‖ 线下，谁先完成就用谁） → 取原料 → 和面 ‖ 和馅 → 包饺子 → 煮饺子 → 吃饺子， 分别用 Promise.race、Promise.all 与 async/await 串起整条流程。

三、核心代码

Promise → race → all → async/await

① 用 Promise 包住 setTimeout，把「等待」变成可 await 的任务

// 每一个流程 = 一个返回 Promise 的函数
function cookStep(name, ms) {
  return new Promise(function (resolve) {
    setTimeout(function () {
      resolve(name);          // Promise 变成 fulfilled
    }, ms);
  });
}

② 竞速：线上、线下同时买，谁先完成就用谁（另一个不会自动取消）

const winner = await Promise.race([
  cookStep("线上买原料", 6000),
  cookStep("线下买原料", 9000)
]);
// 6000ms 的线上先完成 → winner = "线上买原料"，线下仍在后台跑

③ 并行：和面、和馅同时开始，两个都完成才往下走

await Promise.all([
  cookStep("和面", 5000),
  cookStep("和馅", 4000)
]);
// all 要两个都成功；耗时取较长者 5s，而不是 9s

④ async/await 写主流程，读起来像同步代码

async function makeDumplings() {
  // 买原料：线上线下抢单，任一完成即可
  await Promise.race([
    cookStep("线上买原料", 6000),
    cookStep("线下买原料", 9000)
  ]);
  await cookStep("取原料", 3000);

  await Promise.all([
    cookStep("和面", 5000),
    cookStep("和馅", 4000)
  ]);

  await cookStep("包饺子", 3000);
  await cookStep("煮饺子", 4000);
  await cookStep("吃饺子", 2000);
}
makeDumplings();

四、为什么这样做

  • Promise 三种状态：pending（进行中）、fulfilled（成功）、rejected（失败）；resolve() 让它变成成功，状态一旦改变就固定。
  • Promise.race 只取第一个：线上 6s、线下 9s，6 秒时线上完成，整个 race 立刻 fulfilled，后续流程马上继续，不用等 9 秒。
  • 落败的任务不会自动停止：race 只是不再等它，线下购买仍在后台执行（本页日志会在 9 秒时记录"已完成但未采用"）。
  • Promise.all 要全部成功：和面、和馅互不依赖，同时做只需 5 秒；若写成两个连续 await 就要 9 秒，整锅饺子从 23 秒拖到 27 秒。
  • await 会暂停 async 函数但不阻塞页面：等待期间渲染、动画、点击照常响应，只有当前函数停在这一行。
  • async 函数返回 Promise：可继续 .then()，也可在函数内用 try…catch 捕获 await 的异常；finally 适合收尾清理。
  • 何时用哪个：串行依赖用 await；必须全都完成用 all；只要最快的一个用 race；不关心成败、逐个收集结果用 allSettled。
